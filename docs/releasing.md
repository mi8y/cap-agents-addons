# Releasing packages

The repository uses Changesets and npm Trusted Publishing. `.github/workflows/release.yml` publishes with GitHub Actions OIDC; it must not require a long-lived npm token during normal releases.

## Normal release

1. Merge changes containing Changesets into `main`.
2. Review and merge the generated `chore: version packages` pull request.
3. The release workflow builds and publishes every unpublished package version.

`pnpm run publish-packages` runs a readiness check before Changesets publishes. The check blocks the release before any package is published if a public workspace package has not been bootstrapped on npm or has inconsistent publication metadata.

## Add a new public package

npm Trusted Publishing is configured on an existing npm package. A new package therefore needs a one-time manual bootstrap before its first Changesets release is merged.

1. Add the following metadata to its `package.json`:

   ```json
   {
     "publishConfig": {
       "access": "public",
       "provenance": true
     },
     "repository": {
       "type": "git",
       "url": "git+https://github.com/mi8y/cap-agents-plugins.git"
     }
   }
   ```

2. Build and inspect the package contents:

   ```sh
   pnpm build
   npm pack --dry-run --json --workspace <package-name>
   ```

3. Authenticate an npm maintainer with 2FA, then publish the initial version. Provenance is disabled only for this local bootstrap because npm provenance is generated by supported CI providers:

   ```sh
   npm login
   pnpm --filter '<package-name>' publish --access public --no-git-checks --provenance=false
   ```

4. On npmjs.com, open the package's **Settings → Trusted Publisher**, choose **GitHub Actions**, and enter:

   - Organization or user: `mi8y`
   - Repository: `cap-agents-plugins`
   - Workflow filename: `release.yml`
   - Environment name: leave empty
   - Allowed actions: allow direct `npm publish`

5. Run `pnpm release:check`. Only merge the first version-packages pull request after it passes.

## Repository or workflow rename

Trusted Publisher identities are exact and cannot be edited. For every npm package:

1. Delete the old Trusted Publisher connection.
2. Add a connection using the current organization, repository, and workflow filename.
3. Confirm `repository.url` in every package matches the GitHub repository.
4. Run `pnpm release:check` before merging a version-packages pull request.

## Recovery after a manual exact-version bootstrap

If the version from a merged Changesets release was published manually, Changesets will skip that version on its next run and will not create its Git tag or GitHub release. Create those artifacts manually from the version commit, or document that they were intentionally omitted. Packages still unpublished can be released by rerunning the release workflow after their Trusted Publisher settings are corrected.
